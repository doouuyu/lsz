# 《李时珍智能医师》系统开发文档 v1.0

## 第〇部分：总体说明（给工程师的开篇）

**项目本质**：基于大模型API的中医辨证辅助系统，不训练、不微调模型。核心是「提示词工程 + RAG溯源 + 富交互可视化」。

**技术栈建议**：

| 层 | 选型 |
|---|---|
| 前端Web | Vue3 + TypeScript + Vite + Element Plus + ECharts + D3.js |
| 小程序 | uni-app（一套代码可复用Web逻辑）或原生微信小程序 |
| 后端 | Python FastAPI（AI编排友好）或 Node.js NestJS |
| 向量库 | Chroma（轻量，本地可跑）或 Milvus（数据量大时） |
| 大模型API | DeepSeek-V3 / 通义千问-Max / 文心一言（主用一家+备用一家） |
| 数据库 | PostgreSQL（结构化知识+会话）+ Redis（缓存） |
| 部署 | 单台云服务器（4核8G起）+ 对象存储（存PDF报告） |

### 1.1 知识条目 JSON Schema

```json
{
  "$schema": "lishizhen-knowledge-entry-v1",
  "type": "object",
  "properties": {
    "id":              { "type": "string", "description": "唯一ID，如 LSZ-FANG-0001" },
    "category":        { "type": "string", "enum": ["理", "法", "方", "药", "养生"] },
    "subcategory":     { "type": "string", "description": "如 整体观/辨证法/经典方/单味药/四时养生" },
    "title":           { "type": "string", "description": "条目标题" },
    "source": {
      "type": "object",
      "properties": {
        "book":    { "type": "string", "description": "如《本草纲目》" },
        "volume":  { "type": "string", "description": "如 卷十二·草部" },
        "section": { "type": "string", "description": "纲目名，如 黄芪" }
      }
    },
    "original_text":   { "type": "string", "description": "原文摘录" },
    "plain_explanation": { "type": "string", "description": "白话释义" },
    "related_diseases":{ "type": "array", "items": { "type": "string" },
                         "description": "如 [中风, 消渴, 痹证]" },
    "related_syndromes":{ "type": "array", "items": { "type": "string" },
                         "description": "证型，如 [气虚血瘀, 阴虚火旺]" },
    "related_constitution": { "type": "array", "items": { "type": "string" },
                         "description": "体质，如 [气虚质, 阴虚质]" },
    "diagnosis_points":{ "type": "string", "description": "辨证要点" },
    "treatment_method":{ "type": "string", "description": "治法，如 益气活血" },
    "formula": {
      "type": "object",
      "properties": {
        "name":   { "type": "string" },
        "composition": { "type": "array", "items": {
            "type": "object",
            "properties": {
              "herb": {"type":"string"}, "dosage":{"type":"string"},
              "role": {"type":"string","enum":["君","臣","佐","使"]}
            }
        }}
      }
    },
    "contraindication":{ "type": "string", "description": "用药/食用禁忌" },
    "modern_mapping":  { "type": "string", "description": "对应现代健康管理/疾病" },
    "tags":            { "type": "array", "items": { "type": "string" } },
    "verified":        { "type": "boolean", "description": "是否经专家校对" },
    "confidence":      { "type": "number", "description": "0-1，生成置信度" }
  },
  "required": ["id","category","title","source","plain_explanation","tags"]

```

### 1.2 知识图谱关系（用于可视化）

从上述条目自动抽取三元组，存为图谱边表：

```
病证 --[治法]--> 治法
治法 --[代表方]--> 方剂
方剂 --[组成]--> 药材
药材 --[功效]--> 功效标签
病证 --[相关体质]--> 体质
养生法 --[适用季节]--> 季节
```

数据结构：
```json
{ "nodes": [{"id":"消渴","type":"disease","weight":12}, ...],
  "links": [{"source":"消渴","target":"益气养阴","relation":"治法"}, ...] }
```

### 1.3 知识库生成提示词模板（批量产条目用）

```
你是中医文献整理专家，精通李时珍《本草纲目》及其老年病学术思想。
请围绕【{病证名}】这一老年常见病，结合李时珍的学术思想，
生成 {N} 条结构化知识条目，严格输出 JSON 数组。

要求：
1. category 必须从 [理/法/方/药/养生] 中选择，覆盖多个层次。
2. source 字段必须填写真实存在的《本草纲目》卷次与药物纲目；
   若无法确定确切卷次，volume 填"待校"，不得编造具体页码。
3. original_text 仅摘录你确信真实存在的本草纲目药物功效记载；
   不确定的内容放入 plain_explanation 用白话表述，不伪造原文。
4. formula 中药材君臣佐使配伍要符合中医方剂学常识。
5. confidence 字段如实评估（涉及具体卷次出处的条目应标低分）。
6. modern_mapping 将证型对应到现代老年慢病（高血压/糖尿病/冠心病等）。

输出格式遵循以下 Schema：{粘贴1.1的Schema}
```

> **重要工作流**：生成后导出CSV给课题组中医专家，重点校对 `source`、`original_text`、`formula` 三列，校对完的把 `verified` 置 true。只有 verified=true 的条目才进入演示时的"溯源引用"池。


### 3.2 辨证主流程（伪代码）

```python
def diagnose(symptoms, role, session_id):
    # 1. 检查问诊充分性
    inquiry = llm_inquiry(symptoms)
    if not inquiry["ready"]:
        return {"need_more": True, "questions": inquiry["questions"]}

    # 2. RAG检索（混合检索）
    vec_results = vector_db.search(symptoms, top_k=8)
    kw_results  = keyword_search(symptoms, top_k=8)
    context = rerank_merge(vec_results, kw_results, top_k=5)
    # 只保留 verified=true 的条目用于引证

    # 3. 组装prompt并调用大模型
    prompt = build_diagnose_prompt(symptoms, role, context)
    result = llm_call(prompt, response_format="json")

    # 4. 校验JSON结构 + 回填entry_id对应的真实出处链接
    result = validate_and_enrich(result, context)
    save_session(session_id, result)
    return result
```

### 3.3 混合检索（RAG核心）

```
最终得分 = α * 向量余弦相似度 + β * BM25关键词得分
建议 α=0.6, β=0.4，可配置。
检索后做一次 rerank（可用bge-reranker或简单加权），取Top5。
注入prompt前过滤：仅 verified=true 的条目可作为引证源。
```

# 附录C：小程序页面裁剪方案

## C1. 裁剪原则

小程序定位为「基层医生/老年用户的轻量入口」，**只保留高频、轻交互功能**，复杂可视化（力导向图谱、君臣佐使精细图）简化或移除。后端API与Web完全复用。

## C2. Web vs 小程序功能对照

| 功能 | Web | 小程序 | 处理方式 |
|---|---|---|---|
| 仿真辨证 | 完整8步可视化 | ✅保留,简化 | 8步改为竖向卡片列表,雷达图→简单进度条 |
| 四时养生 | 圆盘交互 | ✅保留 | 圆盘→四季Tab切换列表 |
| 五脏调养 | SVG人体图 | ✅保留 | 人体图→五个图标按钮 |
| 基层慢病助手 | 完整 | ✅**主推** | 完整保留,这是小程序核心 |
| 知识图谱 | 力导向大图 | ⚠️简化 | 图谱→关键词搜索+列表,去掉力导向 |
| 角色切换 | 三角色 | ✅保留 | 设置页切换 |
| PDF报告 | 下载 | ✅ | 生成后保存图片/转发给患者 |
| 语音输入 | Web Speech | ✅小程序录音API更稳 | 小程序原生录音 |

## C3. 小程序页面结构（TabBar 4个）

```
TabBar:
[辨证] [慢病] [养生] [我的]

① 辨证 pages/diagnose
   - 症状输入(文字/语音) → 问诊追问 → 竖向8步结果 → 生成报告图

② 慢病 pages/chronic   ← 主推页
   - 病种宫格 → 症状勾选 → 一键方案 → 报告转发

③ 养生 pages/regimen
   - 顶部Tab:[四时][五脏]
   - 四时:春夏秋冬切换
   - 五脏:心肝脾肺肾图标 → 调养详情

④ 我的 pages/mine
   - 角色设置(医生/患者/研究者)
   - 历史辨证记录
   - 知识搜索入口(列表式,无图谱)
   - 关于/免责声明
```

## C4. 小程序专属适配要点

- **字号放大**：面向老年用户，正文最小32rpx，关键操作按钮高度≥88rpx。
- **录音输入优先**：老人打字困难，麦克风按钮放大、显眼。
- **报告以图片输出**：小程序不便下载PDF，辨证报告渲染成长图，支持「保存到相册」「转发给患者/家属」。
- **离线提示**：网络差时给友好提示（呼应合同"网络受限环境"要求，可缓存养生静态内容做轻量离线浏览）。
- **去掉力导向图谱**：小程序canvas性能有限，知识检索改为「搜索框+结果列表」即可。

## C5. 技术建议

用 **uni-app** 开发，一套代码同时产出 H5 和微信小程序，与Web的Vue技术栈统一，最省人力。后端API零改动复用。
