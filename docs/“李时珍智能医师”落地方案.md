
# “李时珍智能医师”落地方案

先说核心判断：你这个项目**完全不需要真正训练或微调大模型，也不需要从零做知识图谱**。当下最务实的路线是 **“LLM存量知识 + 轻量RAG做溯源 + 精心设计的提示词工程 + 富交互前端”** 的组合。我把它叫做“有据可查的壳”——它不是豆包式的裸聊天，而是把中医辨证流程、文献溯源、可视化结果包装成一个看起来有体系、有深度、可演示的专业系统。

下面分块说清楚怎么做。

---

## 一、先解决“指标达标”这件事（最省力的部分）

合同硬指标只有两条：**2000条以上结构化知识条目** + **一份知识库评估报告**。这两条其实是最容易交付的，关键在于“用LLM批量生成 + 人工抽检校对”，而不是真去爬古籍做语料。

**知识条目怎么来：**

设计一套统一的结构化Schema，让大模型按模板批量产出。每条建议包含这些字段：

```
{
  条目ID, 类别(理/法/方/药/养生),
  标题, 出处(《本草纲目》卷X·某部 / 相关医著),
  原文摘录, 白话释义,
  关联病证(中风/消渴/痹证...),
  关联体质, 辨证要点,
  治法, 代表方药, 用药禁忌,
  现代健康管理映射, 关键词标签[]
}
```

用LLM围绕“理—法—方—药—养生”五个层次，按病证×体质×四时养生做笛卡尔组合扩写，2000条一两周就能生成。**但务必做两件事保证可信度**：

1. **出处用真实卷目锚定**。《本草纲目》的卷次、部（草部、谷部、菜部等）、纲目结构是公开常识，LLM能给出基本准确的卷部定位。对“老年常见病用药”这类，引用真实存在的药物条目（如黄芪、人参、何首乌、地黄、杜仲等的功效记载），这些LLM记得很牢，出错率低。
2. **人工抽检10%~15%**。请甲方课题组（孔明望老师那边有中医背景）对随机抽样条目核对原文，凡是LLM编造的卷目或张冠李戴的，修正或剔除。这一步是让“中医大师认可”的命门——**宁可条目少而准，不要多而错**。

**评估报告**就按条目覆盖度、字段完整率、专家抽检准确率、与现代健康管理的映射覆盖等维度写，配图表，10~20页足够。

> 这部分本质是“可控的内容生产”，不是研究。先把它做完，验收的地基就稳了。

## 二、产品形态：网页端为主，小程序为辅

建议 **Web端（PC+移动自适应）做主交付物**，因为演示、投屏、汇报都靠它；小程序作为“基层医生/老年用户”入口的轻量壳，体现“基层适配”指标。两者共用同一套后端API。

理由：经费有限，一套后端 + 响应式前端 + 小程序薄壳，是性价比最高的组合。

## 三、技术架构（轻量、能跑、看起来专业）

```
┌─────────────────────────────────────────────┐
│  前端展示层                                    │
│  Web(Vue/React) + 小程序薄壳                   │
│  富交互：知识图谱可视化、辨证流程动画、         │
│          四时养生轮盘、方药卡片、溯源弹窗        │
└──────────────────┬──────────────────────────┘
                   │ API
┌──────────────────┴──────────────────────────┐
│  应用编排层 (后端 Python/Node)                 │
│  · 提示词工程引擎（辨证思维链模板）             │
│  · 会话/角色管理（医生/患者/研究者）            │
│  · 结果结构化解析（把LLM输出转成可视化JSON）    │
└──────┬──────────────────────┬─────────────────┘
       │                      │
┌──────┴────────┐    ┌────────┴──────────────┐
│ RAG检索模块    │    │ 大模型推理              │
│ 向量库(2000条) │    │ 调用通义/DeepSeek/      │
│ +关键词混合检索│    │ 文心 等API(按量付费)    │
│ →提供"知识溯源"│    │ 不微调，只做提示词控制   │
└───────────────┘    └────────────────────────┘
```

**关键技术选型说明：**

- **大模型**：直接调国产API（DeepSeek、通义千问、文心），按token付费，月成本几百到几千元，完全在预算内。不要本地部署大模型（贵且没必要）。
- **向量库**：用你前面生成的2000条知识库灌进去（Chroma/Milvus/或更简单的FAISS），这就是你的**真RAG**。用户每次提问，先检索Top-K相关条目，拼进提示词，模型回答时**带出处引用**。这一步让“检索增强生成”“知识溯源”从PPT概念变成真实可点击的功能。
- **辨证思维链**：不是训练出来的，而是写在系统提示词里的固定流程模板（见下）。

**这套架构正好把你PPT里画的“平台技术架构”图全部坐实了**——经典文献→向量化→RAG引擎→结构化输出，每一层都有对应的真实实现，而且都是廉价的。

## 四、核心功能模块（对应合同的研究内容）

### 模块1：李时珍智能医师·仿真辨证（主打功能）

这是最出彩的部分。不要做成聊天框，要做成**引导式辨证流程**：

1. 用户描述主诉（支持文字/语音输入，体现“多模态”）
2. 系统**逐步追问**（仿真问诊：寒热、汗、二便、舌脉、睡眠、情志……），像真中医一样四诊合参
3. 后端把对话喂给模型，用**“辨证思维链”提示词**强制模型按固定结构输出：

```
辨证思维链模板（写死在system prompt）：
① 症状归纳 → ② 病位病性判断(脏腑/气血/阴阳) →
③ 证型推断(给出主证+兼证+置信度) →
④ 引经据典(从RAG检索的李时珍/本草纲目条目佐证) →
⑤ 治法确立 → ⑥ 方药建议(君臣佐使拆解) →
⑦ 用药禁忌与调护 → ⑧ 免责提示
```

4. 前端把这8步用**动画分步展示**（不是一坨文字砸出来），每一步有图标、有展开卡片，证型推断画成**雷达图/置信度条**，方药画成**君臣佐使结构图**，每个引证都有“📖出处”可点击弹出原文。

**这一步的视觉冲击 + 逻辑透明，就是区别于豆包裸聊天的核心。**

### 模块2：四时养生与脏腑调养（可视化亮点）

做一个**“四时养生轮盘”**交互组件：圆盘分春夏秋冬，点击某季节→展开该季节的起居/膳食/情志/简易功法建议，配李时珍养生论述引文。再做一个**“五脏调养图”**，点击心肝脾肺肾任一脏→对应食疗、药膳、节气养生。内容全部LLM预生成 + 人工校，做成静态+半动态数据，不必每次调模型，**省成本又快**。

### 模块3：基层老年慢病管理助手（体现“基层适配”指标）

针对高血压、糖尿病（消渴）、冠心病等，做**“一键辨证”**卡片：用户选病种+勾选几个常见症状→生成中医调护方案（辨证分型+食疗+起居+简易功法+随访提醒）。输出**“一键报告生成”**——生成规范化PDF诊疗记录可下载/打印。这直接命中合同里“一键辨证、智能方药推荐、养生处方生成器、一键报告”的描述。

### 模块4：知识库检索与图谱浏览（体现“知识库”交付）

- **语义检索框**：输入“老年人失眠李时珍怎么调”，返回相关条目+出处。
- **知识图谱可视化**：用 ECharts/D3 把2000条知识的“病证—治法—方—药”关系画成可拖拽的关系网络图。**这张图是汇报时最唬人的一页**，技术上就是把结构化数据渲染成力导向图，几天就能做。

### 模块5：角色自适应（体现“用户意图感知”指标）

顶部切换“医生／患者／研究者”三种模式，本质是切换提示词：医生模式给术语+方药剂量，患者模式给白话+食疗，研究者模式给文献引证+理论溯源。一个参数控制，成本极低，但完美对应合同里“自适应交互界面”。

## 五、怎么让“中医大师认可”

这是项目能不能过的关键，给四个具体抓手：

1. **真实文献锚定**：所有辨证结论必须带出处，且出处经过抽检校对。大师最反感的是“一本正经胡说八道”，只要溯源链路真实，可信度立刻上来。
2. **辨证逻辑符合中医范式**：思维链严格走“理法方药”，不跳步、不西医化。这是中医专家判断“是否懂行”的第一眼标准。
3. **保留专家可修订入口**：在后台留一个“专家审核/修正”功能，让课题组中医专家能编辑知识条目和辨证模板。这既是真实可用性，也是汇报时的加分项（“人在回路”“专家共识闭环”）。
4. **明确免责与定位**：每次辨证输出都附“本系统为学术研究与辅助参考，不替代执业医师诊断”。这既合规（合同第8.4条数据合规、医疗风险），也让专家放心——你不是在替代他们，而是传承+赋能。

1. 打开首页 → 展示“平台技术架构”动态图（和PPT一致，呼应）
2. 切到**仿真辨证** → 输入一个老年消渴（糖尿病）案例 → 系统逐步问诊 → 八步思维链动画展开 → 证型雷达图 → 君臣佐使方药图 → 点开📖看到《本草纲目》出处原文
3. 一键生成PDF诊疗报告 → 下载展示
4. 切到**知识图谱** → 拖动力导向大图，搜索“痹证”高亮关联路径
5. 切到**四时养生轮盘** → 点“冬季”→ 脏腑调养建议
6. 切**角色模式** → 同一问题，患者模式 vs 医生模式输出对比
7. 掏出手机扫码 → 小程序同款功能，体现“基层可用”
